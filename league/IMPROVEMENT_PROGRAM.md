# Improvement Program — All Leagues (P1–P6)

User decision, 2026-11-11 03:25 WIB: the six proposals in
`league/AUDIT.md` §6 (which came out of `league/EXPERT_METHOD_STUDY.md`
and the final league audit) are ADOPTED as a program of work for ALL
leagues in the league tree. This charter governs that program.

## Launch trigger and sequence

- The program starts when the final league audit closes (AUDIT.md
  marked complete). Until then, this charter is registration only.
- Work order: each proposal's own Gate Zero test runs FIRST, exactly
  as pre-registered in AUDIT.md §6 (hypothesis, Gate Zero, gate,
  kill rule). A proposal is adopted only if its Gate Zero passes;
  on failure it dies by its own kill rule — no silent retries with
  changed thresholds.
- Suggested execution order by dependency and cost: P2 + P6
  (process guards, ~0.5 d each), P5 (shared gate library, ~4 d —
  it makes every later re-run safe), P1 + P4 (artefact replays,
  ~2 d each), P3 (variance-component ratings, ~5 d).

## The six workstreams (full text: AUDIT.md §6)

- P1 — Time-ordered forward-stability admission leg for features.
- P2 — Design-seal the EDA stage (dev-era seasons only in EDA and
  reliability artefacts; sealed aggregates generated by the
  coordinator after the design freezes, never shown to builders).
- P3 — Variance-component ratings (partial pooling) replacing fixed
  ridge/prior constants; the only workstream reaching scores-only
  leagues.
- P4 — Sanctioned recalibration arm (level-only refit on the most
  recent dev slice, pre-registered, competing under the same legs).
- P5 — Guards in code, not procedure: shared gate library (dev-pass
  assertion before any sealed load; prereg tokens parsed
  mechanically; per-league derivation of template constants such
  as the M_BAR class; one calibration sign convention).
- P6 — Worst-fold dev reporting in every verdict (information only,
  no gate change).

## Fast lanes (user decision, 2026-11-11 03:56 WIB)

The user does not accept waiting for future fixtures as the only
route to new verdicts. Two governed fast lanes are adopted:

- **Lane 1 — unread sealed windows (starts at program launch).**
  Candidates that failed at the DEV gate (or otherwise never had
  their sealed window read) still hold genuinely sealed final
  seasons. Inventory them from AUDIT.md §1's classification. They
  may re-enter under this program as NEW candidates with fresh
  preregistration, judged on those unread windows: one read,
  verdict final, no iteration against the window after the read.
  Method-design knowledge drawn from OTHER leagues' failures is
  permitted (that is ordinary cross-study learning); nothing about
  a candidate's own sealed contents is known or used, before or
  after its single read.
- **Lane 2 — provisional shipping, live verdict (starts only after
  the relevant workstream's method is frozen AND validated on
  Lane 1 windows).** A candidate whose old sealed window is burned
  may be re-screened on that window under the frozen method. If it
  passes the screen, it ships as PROVISIONAL (the program's
  existing provisional semantics): labelled provisional in the
  runner and in reports, live-graded daily. The screen is NOT a
  verdict — the live record is. Pre-registered live rule: after
  ≥150 settled predictions, the market is automatically REVOKED
  if its live calibration error sits outside the same 1-SE band
  the original gate used; promotion to a clean PASS is never
  automatic and requires the user's word after the live evidence
  is reviewed.

## Rules that do not change

- Gates stay pre-registered; nothing in this program moves a gate
  after results are seen.
- Burned sealed windows stay burned FOR CLEAN VERDICTS. Any clean
  re-test of an improved candidate uses a NEW sealed window
  (future fixtures or an unread season — Lane 1), pre-registered
  before the read. The sole exception is Lane 2's provisional
  route above, whose verdict is the live record, never the
  burned window.
- No retroactive re-passing: a market that failed under the old
  method is NOT re-passed as a clean PASS under corrected or
  improved code. It may only re-enter as a new candidate under
  this program's preregistration (Lane 1), or ship provisionally
  under Lane 2's live-verdict rule.
- Runner membership changes only when a candidate passes the full
  gate under the new method; live markets are never silently
  swapped.
- Production top-5 is untouched by this program.
- Implementation on Codex luna (`~/.local/bin/codex`, stdin closed);
  sol only for a closing audit if the user orders one. Local
  commits only, explicit paths, never push.
