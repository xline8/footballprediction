# Pre-registration — T-QA (QA-QatarStars total shots): NOT BUILT

Frozen: 2026-11-10, before any fitting. Design authority:
`analysis/MODEL_DESIGN.md` (T-QA); evidence EDA F1/F2/F3/F6.

T-QA is **not built**, by feasibility, recorded here so the absence
is an auditable decision and not an omission:

- The total-shots target exists ONLY in the stats era (2025/2026+):
  0 matches with a stats feed in 2021/2022–2023/2024, 1 match in
  2024/2025, 132/132 in 2025/2026. There is no dev season, no warm-up
  season, and no scored dev window at all before the virgin season
  (2025/2026) itself. This is the FI total-shots case in its strongest
  form: not a definition break within a dev window, but the complete
  absence of a dev window.
- Trait reliability is not measurable on dev (split-half r null,
  n = 0 teams — the target is absent in every dev season), and no
  1H share is computable on dev (0 matches with FirstHalf/SecondHalf
  splits in dev; the single 2024/2025 stats match has All only), so no
  line can be selected and no halves constant frozen.
- No arm, window, or line is therefore frozen, nothing is fitted,
  and the virgin is not read for total shots. The frozen split
  (dev ≤ 2024/2025, virgin 2025/2026, 2026/2027 untouched reserve) is
  NOT moved to manufacture a dev window: re-splitting after seeing the
  era break would be post-hoc window shopping. If future seasons add
  dev-era stats seasons, T-QA can be pre-registered fresh — it may not
  be rescued inside this prereg.

Verdict: `reports/T_QA_VERDICT.md` (not-buildable).
