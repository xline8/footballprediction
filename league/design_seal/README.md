# P2 — Design-seal tooling for the EDA stage

Implements proposal P2 of `league/AUDIT.md` §6, adopted in
`league/IMPROVEMENT_PROGRAM.md`.

## The design rule (going forward)

> **EDA and reliability artefacts may only be computed on DEV-ERA
> seasons.** Sealed-season aggregates are generated by the coordinator
> after the design document freezes, and are never shown to builders.

The old program was fit-sealed but not design-sealed (AUDIT.md §4b):
EDA workbooks inspected aggregates across all seasons, including the
sealed (virgin) season, so sealed-season levels were printed in design
documents in front of the builder. This package is the tooling that
makes the rule mechanical rather than procedural.

## What is here

| File | What it does |
|---|---|
| `seal.py` | Core library. Parses a league's `config.yaml` (no PyYAML in the project venv, so a targeted parser) into a `Seal`: dev-era seasons (`dev_seed` + `dev_period`) vs sealed seasons (`virgin_primary` + `virgin_confirmatory` / `virgin*`, with fallbacks for the config variants in the tree). Provides `filter_rows()` (drop sealed rows from match data), `assert_dev_only()` (raise if a JSON-like artefact contains a sealed-season key/value), `find_sealed_references()` and `text_mentions_sealed()`. |
| `eda_filter.py` | CLI an EDA generator wraps: `filter-csv` writes a dev-only copy of a matches CSV; `check-json` fails (exit 1) if an artefact contains sealed-season references. |
| `contamination_scan.py` | The contamination scanner: audits every league's existing `analysis/` artefacts against that league's sealed season(s) and classifies each league DATA (a sealed-season aggregate row/key is present), MENTION (sealed season named, no aggregate row found), CLEAN, or NO_SEAL (config defines no sealed window). |
| `self_test.py` | Proof on AE-ProLeague's real data: pre-filter contamination is possible (and shipped — its `eda_numbers.json` fails `assert_dev_only`), post-filter output contains zero sealed rows. |

## Usage in a new EDA generator

```python
from league.design_seal.seal import load_seal, filter_rows, assert_dev_only

seal = load_seal(LEAGUE_DIR)                 # partition from the league's own config
rows = filter_rows(all_match_rows, seal)     # sealed rows can no longer enter any table
# ... compute levels / reliability / halves on `rows` only ...
assert_dev_only(eda_numbers, seal, "eda_numbers.json")   # before writing the artefact
```

CLI equivalents (project python, from the repo root):

```bash
.venv/bin/python -m league.design_seal.self_test
.venv/bin/python -m league.design_seal.eda_filter filter-csv league/<L> league/<L>/data/<matches>.csv /tmp/dev_only.csv
.venv/bin/python -m league.design_seal.eda_filter check-json league/<L> league/<L>/analysis/eda_numbers.json
.venv/bin/python -m league.design_seal.contamination_scan --out-json <census.json> --out-md <census.md>
```

## Gate Zero framing (pre-registered, AUDIT.md §6)

P2's Gate Zero is a **process control, not a statistic**: apply the
design-seal to the program's **first 10 NEW builds** and audit their
artefacts for sealed-season contamination — **target: zero rows**.
It cannot complete today, because those builds have not happened.
What exists today is the tooling, the scanner, a passing self-test,
and the baseline contamination census of the old program (see
`league/improvement_scratch/P2P6/report.md`). No Gate Zero verdict
is claimed.

## Scanner limits (stated plainly)

- Artefacts are scanned under `analysis/` only, in text formats
  (`.json`, `.md`, `.txt`, `.csv`, `.py`). Chart images (PNG) are not
  OCR'd; a chart plotted from contaminated numbers is caught through
  its source JSON/MD, not the image.
- Generators that iterate a `SEASONS` list including the sealed season
  without naming it literally are caught through their outputs
  (JSON keys / MD table rows), not through the code scan (`PY_REF`
  only fires on a literal season string).
- A DATA hit means a sealed-season aggregate was *present in a
  builder-facing artefact*. It does not by itself prove the builder
  used it in a design decision — that judgement was AUDIT.md §3's,
  made case by case for the 99 sealed-window failures.
